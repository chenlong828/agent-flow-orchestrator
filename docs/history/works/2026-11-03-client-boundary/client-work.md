# agent-flow-client 侧工作清单

> 定位：从[边界与职责设计](boundary-design.md)拆出的 client 侧工作项，用于 client 项目立项与排期。仍停留在方案与流程框架层，不写端点、字段、目录布局与代码。

## 1. client 的定位与边界

client 是执行面，只负责“在本机把节点执行出来”。它拥有：

- 实例/分支工作区、技能落地、脚本、本地产物；
- DSH profile/技能根、进程组与 ACP session；
- 本地日志、会话记录、恢复 journal；
- 少量结果的组装与上报。

它不做：

- 不决定下一节点、不判评审、不拆 fan-out、不做回退；
- 不读调度器数据库、不解析专家/技能装配；
- 不上传产物、不传完整会话记录；
- 不修改调度器，不替调度器维护实例/节点状态。

从调度器拿到的输入：节点执行请求（prompt、输出契约、超时）、session 绑定后的技能集合、取消/关闭控制、client 身份与凭据。  
交给调度器的输出：session id 绑定、少量结果、心跳/容量、错误。

## 1.1 S0 已确认的约束

- **技能可见性**：建 session 后立即写技能，首次 prompt 可见；同 session 替换也可见；不需要额外屏障，保留“先建 session 再取技能”。
- **技能根隔离**：DSH 的可见技能是多根并集。要求是**屏蔽全局根、保留项目根**：`includeDefaultRoots: true` 下项目 `.dsh/skills` 与 `.agents/skills` 都保留；把 `dshHome`、`agentsHome`、`bundledSkillDir` 指向真实空目录，屏蔽用户根与打包根。不要用 `DSH_HOME` 环境变量去关（会影响 settings/credentials）；只覆盖 skill-filesystem 的 config。
- **进程模型**：一个活跃工作区一个 DSH 进程；同一工作区顺序节点共享进程；fan-out 分支各自工作区与进程。
- **崩溃清理**：SIGKILL DSH 后工具子进程可能存活；不能依赖 ACP close，必须按进程组/作业树清理；崩溃 session 与 lock 需清理或忽略。
- **权限**：permission 请求可能没有 `title/kind`，只能按 `options` 整体放权，不能按工具名做策略。
- **结果**：用量从 `usage_update` 事件取；第二次 close 的 `-32602` 视为幂等；错误按 code/message 映射。
- **技能格式**：顶层 `<name>/SKILL.md` 或 `<name>.md`，`name`/`description` 必填；嵌套不可见。

### CW-01 CLI 与运行模式

- 常驻模式：循环领取任务、维护租约、上报心跳；单次模式：本地假任务或调试执行。
- 配置：调度器地址、凭据、DSH 路径/版本、工作区根、并发上限、日志级别。
- 健康检查与启动自检：DSH 可用、工作区可写、凭据存在、版本兼容。

出口：两种模式共用同一执行内核；配置错误能明确报出。

### CW-02 连接与租约

- 注册与身份：首次引导、凭据保存、版本上报；心跳携带容量与存活。
- 领取：只领取绑定到本 client 的实例任务；按容量领取；租约到期前续约。
- 上报：session id 绑定、少量结果、错误；重复上报幂等。
- 版本协商：不兼容时拒绝领取并给出原因，而不是带病执行。

出口：断网、重复投递、租约过期、迟到结果都有确定行为。

### CW-03 工作区

- 实例/分支工作区：按实例准备主工作区；顺序节点共享；fan-out 子任务独立（clone/worktree）。
- 进程边界：一个活跃工作区对应一个 DSH 进程；共享工作区跨实例与技能目录争用不默认启用。
- 路径约束：所有读写限制在工作区根内；不跟随越界路径。
- 生命周期：实例结束时按策略保留/清理；失败/取消时也走同一清理路径。

出口：三种模式可创建、复用、清理；并发 fan-out 不互相踩目录。

### CW-04 资产

- 技能包：从调度器给定来源下载，校验完整性，解压到工作区。
- 落地格式：顶层 `<name>/SKILL.md` 或 `<name>.md`；`name`/`description` 必填；拒绝嵌套。
- 刷新：按节点组合替换当前技能状态，不叠加；失败不留下半套。
- 技能根：在 DSH profile 的 skill-filesystem 配置中保持 `includeDefaultRoots: true`，把 `dshHome`、`agentsHome`、`bundledSkillDir` 指向真实空目录；项目根保留，节点技能落在 `.dsh/skills` 或 `.agents/skills`。注意 patch 对目标行是整份 config 替换，不合并；只写这三个字段，其余走 schema 默认值。
- 脚本：随技能包落地，赋予执行权限；把可用脚本路径提供给模型；不执行脚本、不判断结果。
- 缓存：重复技能包可复用；缓存失效与清理有规则。

出口：模型只看到当前节点的技能组合；损坏包能报错并阻止执行。

### CW-05 运行时

- DSH 供给：定位、版本校验、固定版本/commit；不可用时明确报错；不静默降级。
- 进程：一个活跃工作区一个 DSH 进程；同一工作区顺序节点共享；fan-out 分支各自进程；实例结束退出所有分支。
- 进程清理：按进程组/作业树管理；结束时杀组，不依赖 ACP close。
- session：一个可执行节点一个 session；建 session 后上报 id；prompt 后消费事件；结束关闭。
- 取消/关闭：取消当前 session；close 幂等（第二次 `-32602` 视为已关闭）；实例关闭时清理剩余 session 与进程。
- 权限：按 permission 的 `options` 应答 `allow_once`；不能按工具名做策略。
- 事件：收集模型输出、工具调用、用量等执行事实；不跨边界传全文。

出口：会话生命周期与实例生命周期清晰；取消/关闭无残留。

### CW-06 结果

- 从 session 输出中提取最终消息；按输出契约原样回传，不解释业务字段。
- 组装少量结果：状态、停止原因、用量、session id、错误；用量从 `usage_update` 事件收集。
- 错误映射：把本地失败翻译成调度器可判定的错误类别；区分可重试与不可重试。

出口：成功/失败/取消都有一致的结果形态；调度器能据此推进或重试。

### CW-07 恢复

- 本地 journal：记录实例、节点、session、进程、尝试次数的执行事实。
- 孤儿清理：重启后按进程组/作业树识别并清理上一次遗留的 DSH 进程/工具子进程；清理或忽略崩溃 session 与 lock。
- 重启恢复：重新注册、重新领取、重跑当前节点；不依赖 session 恢复。
- 离线：本地不自行推进流程；恢复后按调度器指令继续。
- 迟到结果：按调度器裁决处理，不自行覆盖新尝试。

出口：进程崩溃、网络中断、实例中断后都能回到可继续的状态。

### CW-08 安全

- 凭据：只存本地安全位置；不进日志、不进结果、不进 prompt。
- 完整性：技能包校验；拒绝不可信来源；防路径穿越/压缩包越界。
- 受控配置：DSH profile/技能根由 client 管理；默认用户/项目技能根不得绕过节点组合。
- 权限边界：permission 可能不含工具名，不把工具名白名单当保证。
- 执行信任：远程下发的 prompt 与脚本具有执行影响力；按用户授权与审计策略执行。
- 数据：本地日志脱敏；不上传会话全文。

出口：通过安全评审；无明文密钥；越界路径被拒绝。

### CW-09 观测

- 本地日志：按实例/节点/session 关联；包含关键阶段与错误。
- 诊断：`doctor` 类自检（DSH、工作区、凭据、网络），便于用户排障。
- 可选进度事件：只上报状态级信息，不传全文。

出口：一个失败节点能从本地日志定位到阶段与原因。

### CW-10 打包与测试

- 单二进制分发；目标平台（macOS/Linux 先行）；版本号与升级策略。
- 假调度器：本地模拟注册/领取/session/结果，支撑 S0/S1 测试。
- S0/S1 用例：技能可见性、受控技能根、一工作区一进程、刷新、脚本、权限、取消、崩溃恢复、幂等、用量。
- 升级：client 与 DSH 版本兼容检查。

出口：目标平台可安装运行；回归用例可重复执行。

## 3. S0 结果与后续

S0 已完成 12 项 P0，11 项通过；失败项是 S0-11（崩溃后工具子进程孤儿）。核心结论：

1. 技能在 prompt 时读取；建 session 后写技能可见，同 session 替换也可见——保留“先建 session 再取技能”，不需要屏障。
2. 每节点替换在同进程内可行，不必重启；skill-filesystem 配置可屏蔽全局根、保留项目根。
3. 同进程多 session、不同 cwd 可按默认项目根隔离；但本文选择“一工作区一进程”，不依赖同一进程切换不同技能根。
4. 脚本可执行；权限只能按 options 整体放权；close/cancel 可用；用量从事件流取。
5. S0-11：SIGKILL DSH 后工具子进程存活，必须按进程组/作业树清理。

S1 前置：

- 全局根屏蔽配置 + 一工作区一进程的组合验收；
- 进程组/作业树清理与崩溃 session/lock 处理；
- 固定 DSH 版本/commit，并复跑 S0 关键用例。

未覆盖（不阻塞 S1）：permission 拒绝路径、`session/resume`、subagent/native、Windows/Linux。

## 4. 对调度器的依赖

client 在 S1 前需要调度器提供并冻结：

- client 身份与凭据；
- 节点执行请求（prompt、输出契约、超时）；
- session 绑定与技能集合；
- 结果接收与确认；
- 取消/关闭控制；
- 契约版本与兼容规则。

client 不自行定义字段；契约由调度器侧维护，client 消费。

## 6. 明确不做

- 不做编排决策（下一节点、评审、分支、fan-out 拆分、回退）；
- 不做调度器状态机、数据库、接口实现；
- 不做 DSH 改造；
- 不做产物上传与跨 client 迁移；
- 不做 UI。
