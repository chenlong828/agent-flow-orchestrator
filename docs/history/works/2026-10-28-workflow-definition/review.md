# 工作流定义 P1 第二轮评审材料

> 状态：第二轮评审通过，P1 已冻结（2026-10-29）。材料：[architecture.md](architecture.md)、[component-spec.md](component-spec.md)、[contract.md](contract.md)、[schema.md](schema.md)。第一轮评审已通过，本轮目标是冻结设计，不写代码。

## 1 本轮要评审什么

1. `CMP-workflow` 的组件边界、数据所有权、依赖方向；
2. 10 个工作流端点、DTO、错误码、并发语义；
3. 三张表的 DDL、索引、外键、数据库修改顺序；
4. 图形状校验与语义警告的边界；

6. DSL 导出/导入规则；
7. 任务拆分与冻结门槛。

## 2 本轮已确认

| 决策 | 结论 |
|---|---|
| B3 定义 | 只存 `graph`，取消 `behavior` |
| `type` | 自由文本标签，1–40 字，可修改，不参与图校验 |
| 名称 | 大小写不敏感唯一 |
| 节点专家矩阵 | `start`/`end`/`agent`/`review`/`fanout`/`fanin` 必填；`confirm` 禁止 |

| DSL 格式 | JSON 是唯一导入格式；YAML 只用于导出 |
| 发布/版本 | 完全取消 |
| 保存校验 | 形状错误阻断；语义问题保存成功并给警告 |
| 并发策略 | 专家删除不做额外并发控制；保留 revision/If-Match；删除只靠 FK |

## 3 默认规则与待确认项

### D1 复制自动后缀的细节

已确认“自动后缀”，默认规则：

- `name` 可省略，默认 `"{源名称} 副本"`；
- 若名称已存在，依次追加 ` (2)`、` (3)`，最多到 ` (99)`；
- 显式传入的 `name` 冲突时也自动后缀，保持行为一致；
- 追加后仍超过 80 字，先截断基名再加后缀；
- 99 个都冲突返回 409 `name_conflict`，不再无限重试。

### D2 保存/导入缺失专家的不对称（已接受）

- 保存：`expertId` 不存在返回 400，事务回滚；
- 导入：缺失专家清空为 `null`，返回 warning；
- 校验未保存草稿：缺失专家给 warning，不写库。

### D3 低并发 MVP 的并发策略（已确认）

- 当前 QPS < 1，不为专家删除的并发窗口增加额外锁、串行化或自动重试；
- 工作流更新/删除/保存仍保留 B1 的 `revision` + `If-Match`，这是已有契约，不额外加成本；
- 专家删除保留 guard 做常规提示；并发窗口由 `workflow_expert_ref.expert_id` 的 `RESTRICT` 外键兜底，冲突返回 409 `referenced`；
- FK 冲突时不再重查 guard、不自动重试，客户端重读即可。

### D4 数据库修改编号（不是数据搬迁）

- 本工序不搬迁任何旧数据；
- 所谓 `0005_workflow.sql` 只是数据库修改执行器里的脚本编号，内容仅 `create table`；
- Skill 包工序可能先占用编号，实现时按下一个可用号落，不在本轮写死。
