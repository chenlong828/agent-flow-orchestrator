# 工序：执行面契约 v2 接口验证

## 背景

`agent-flow-client` 已按 `executor-http-v2` 完成实现（client 仓库提交 `e047e0a`「按 executor contract v2 重写 client 契约实现」、`4c8f8b0`「补 serve 联调收口与桩调度器脚本」），并提交了 client 侧契约副本。调度器侧（本仓库）对该契约仍无实现：`src/`、`tests/`、`db/` 无 executor 路由或任务表，本条已由 2026-11-10 契约工序的记录与本次复核共同确认。

契约验收面（§10.1 桩调度器最小面、§10.2 client 门禁）此前只有 client 侧自测，没有从调度器侧（契约权威方）发起的接口验证。本工序补这一环：以契约条款为准，对 client 实现做运行时与静态核对，产出可复跑的验证证据与差异清单。

## 目标

1. 在调度器侧写一个最小桩服务（仅本工序内使用，不进产品代码），按契约 §2/§4 实现三个端点的服务端行为，驱动真实 client `serve` 完成接口级验证。
2. 逐条核对契约 `P-01`…`P-03`、`C-01`…`C-09`、§3 常量与错误码，标出「符合 / 偏离 / 契约自相矛盾 / 未覆盖」。
3. 给出可关闭工序清单：哪些针对本契约的 `works/` 工序已具备收口条件，哪些仍需保持开放，各给证据。

## 范围

- 契约文本：本仓库 `docs/design/contracts/executor-http-v2.md`（权威，2026-11-10 从契约工序移入 design 层）。
- 被验证实现：`agent-flow-client` 的 `src/components/{gateway,executor,cli,assets,result,store}/`（只读；允许运行其测试与桩，不改其代码）。
- 验证脚本与运行产物只放本工序目录。

## 非目标

- 不实现调度器侧 executor 端点、不建任务表、不改 OpenAPI（属 P1 实现工序，另立）。
- 不改 client 仓库任何文件；发现的偏离只记录，不在本工序修复。
- 不验证真实 DSH/LLM 行为（用 client 的 fake ACP 夹具替代，只验协议面）。

## 验收标准

| 项 | 判据 |
|---|---|
| 可复跑 | 验证脚本一条命令跑完，输出逐项 PASS/FAIL 与证据 |
| 条款可追溯 | 每条核对结论能指到契约章节与 client 文件行号 |
| 差异分级 | 偏离按「阻塞联调 / 需修订契约 / 建议清理」分级，不混为一谈 |
| 可关闭判定 | 每个工序的关闭/保留都有证据，不写「应该可以」 |
