# 2026-10-25 项目边界与早期开放问题归档

## 背景

项目初始化与 B1 实施期间，`docs/plan/open-questions.md` 积累了 OQ-1～OQ-4。它们多来自对目录结构、同名项目和常见服务形态的早期推断，没有外部引用证据；其中“UI 是否是需求来源”“是否同时做 CLI/库”没有用户确认，“首个端到端流程”也未提出。OQ-4 只确认过先做 B1。

B1 完成后，这些条目仍以“待定 / 部分解决”留在计划层，容易被误读为后续工作的阻塞项。2026-10-25 用户明确项目边界，并要求将这些早期问题直接归档。

## 决策

1. **对外形态只有 HTTP API**：本仓库提供 `/api/v1` 业务端点与 `/healthz`；不提供 CLI，不提供 SDK/库，也不提供 UI。
2. **UI 是独立项目**：`agent-flow-ui` 不在本仓库内，本仓库不包含、不启动、不修改 UI，也不把 UI 作为需求来源或验收前置。跨项目只以 REST 契约为界面；UI 是否、如何消费 API 由该项目自行决定。
3. **OQ-1～OQ-4 全部关闭并归档**：不再作为开放问题、里程碑门禁或排期依据；条目保留在 `docs/plan/open-questions.md` 供追溯。
4. **未来问题按实际需求另立**：运行形态、ACP 执行模型、首个端到端流程等，等真实需求或工序出现时再设计，不提前补答案。
5. **CORS 不在本仓库范围**：本仓库不配置 CORS；外部浏览器若跨源调用，由部署层同源代理或调用方处理。

## 被否决的方案

- **把 `agent-flow-ui` 作为本仓库的需求来源与验收蓝本**：两个项目独立，UI 不是已确认的需求输入。
- **同时提供 CLI 或库接口**：当前没有消费方与需求，提前提供会扩大维护面。
- **在本仓库内提供 UI 或 UI 适配层**：UI 属于另一个项目，接入工作不进本仓库。
- **继续保留 OQ-1～OQ-4 作为待定项**：这些是早期推断，不是用户提出的问题；继续挂着会误导排期与设计。

## 后果

- `README.md`、`AGENTS.md`、`docs/design/architecture.md`、`docs/plan/roadmap.md`、`docs/plan/open-questions.md` 同步项目边界。
- B1 的 REST 契约、代码与测试不变；本次只改文档。
- 后续新问题仍按 `open-questions.md` 登记；已关闭条目不删除，结论指向本记录。
