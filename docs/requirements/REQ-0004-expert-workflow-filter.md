# REQ-0004 专家列表按工作流筛选

## 1 场景叙述

专家维护者在「专家管理」页想先选定一条或多条工作流，只看这些流程节点实际绑定过的专家，再在结果里搜索、按启停过滤或分页；不选流程时保持现在的全量列表。

结果：同一个专家列表接口既能支撑「全部专家」，也能支撑「某条流程用到的专家」，前台不必先拉工作流定义、再自行解析节点与专家的绑定关系。

## 2 价值

不做的话，专家管理页只能显示全量专家；要按流程过滤，前台得先取工作流列表、再逐条取详情、从 `graph.nodes[].expertId` 里拼出集合，既多请求又容易与 `workflow_expert_ref` 的口径不一致。流程编辑、运行排障时想确认「这条流程到底用了哪些专家」也只能人工对照画布。

## 3 非目标

- 不返回流程节点明细（节点名、节点类型、节点顺序）；响应仍是现有专家卡片 DTO。
- 不做「按节点顺序排列专家」或「流程步骤 → 专家」的可视化视图。
- 不在专家列表项上增加所属工作流/节点标注。
- 不增加「未加入任何流程」的专用筛选值；未绑定专家只在未传 `workflowId` 的全量列表出现。
- 不做按工作流类型（`type`）筛选；本次只按具体工作流 ID。
- 不改变专家删除引用保护、`refCount` 口径、工作流保存校验或运行编排。
- 不新增数据库表、列或端点。

## 4 约束

- 过滤走现有 `GET /api/v1/experts`，新增可重复的 `workflowId` 查询参数；不传时行为与现契约完全一致。
- 多个 `workflowId` 取并集；同一专家被多个流程引用只返回一次；过滤条件与 `q`、`enabled`、`sort`、分页同时生效，`total` 反映过滤后的总数。
- `workflowId` 必须是 UUID；非法值返回 `400 validation_error`，`details.field="workflowId"`。
- 未知但格式合法的 `workflowId` 返回空列表，不返回 404；不额外校验工作流是否存在。
- 专家到流程的绑定以 `workflow_expert_ref` 为准，不读工作流图 JSON 重新解析；不新增反向写入口。
- 兼容性：只做加法；旧调用方不传新参数时响应不变。

## 5 影响场景

- `SCN-0001` 专家定义与装配管理：修改 `R2` 的列表读断言，新增「按一条或多条 `workflowId` 过滤、并集、未绑定专家只在全量出现」的验收。
