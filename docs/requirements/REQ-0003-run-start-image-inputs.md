# REQ-0003 启动运行支持图片初始资料

## 1 场景叙述

研发人员在发起一次工作流运行时，除了填写 markdown 启动意图，还可以从剪贴板粘贴、拖放或选择一张或多张图片（PNG/JPEG/WebP/GIF）。图片在提交前只在浏览器本地暂存（缩略图/校验/删除）；点击「发起运行」时逐张上传、暂存，全部成功后服务端把选中的暂存图片绑定到本次 run。client 取到首节点任务后，把图片写入该 run 的 `<task-space>/inputs/`，各节点模型在需要时用 `read_image` 查看；运行详情/人工确认页也能看到这些图片。

结果：一次启动的「文字诉求 + 图片初始资料」一起进入同一个 run；图片不会因为 prompt 大小限制或服务端无法访问工作区而丢失。

## 2 价值

不做的话，用户只能把截图内容手写成文字，或把图片另行放到工作区再在意图里写路径；评审、界面验收、报错定位这类以图片为主的资料无法可靠进入节点上下文。task-space 已经是 run 的上下文载体，但缺少把用户图片送进去的入口。

## 3 非目标

- 不做通用文件（PDF、docx、代码文件）上传；首期只支持图片。
- 不做图片编辑、裁剪、旋转、OCR、压缩、缩略图服务；原图上传，展示由 UI 缩放。
- 不做断点续传、上传队列持久化、跨会话复用暂存图片。
- 不做运行结束后从归档浏览图片（沿用 `OQ-34`）。
- 不做管理面鉴权；产品端点仍按现状无鉴权，生产前另立工序。
- 不做多模态模型切换的产品化；client 侧模型配置与验证作为前置条件。
- 不改变 `confirm` / `review` 的判定语义；初始资料只是 task-space 里的文件。

## 4 约束

- 服务端不访问 client 工作区（`REQ-0001` §4）；图片必须由 client 拉取并写入 task-space，编排不直接写 `workspacePath`。
- 上传采用「提交时上传」：点「发起运行」后 UI 逐张调用独立暂存端点，全部成功后启动引用 `inputId`；上传时机对产品契约不可见，不把图片字节塞进 prompt 或任务信封。
- 旧 client 必须被显式拒绝，不能静默丢图；能力协商与启动闸门由设计定。
- 暂存项**不设 TTL**；启动失败不消耗暂存项，允许重试；未绑定的暂存项由 UI `DELETE` 或运维清理；绑定只在启动事务内完成。
- 只支持图片（PNG/JPEG/WebP/GIF），不接受 SVG；首期上限 8 张 / 单张 8 MiB / 合计 20 MiB；运行详情带缩略图（`API-55/56`）。
- 执行面契约只做加法，不升 `X-Executor-Protocol` 版本；`TaskRequest` 不改（`runId` 已有）。
- client 写入职责扩展：除创建 task-space 目录外，只额外写入本 run 声明的 `inputs/`；`intent.md` 等仍由节点模型写。
- 项目边界不变：本仓库只做编排契约与实现；UI 已在 `agent-flow-ui` 实现（[result](../../../agent-flow-ui/docs/history/works/2026-11-19-run-start-images/result.md)）；client 在其仓库实现。

## 5 影响场景

- `SCN-0301` 运行启动与节点推进：新增「带图启动时 prompt 含初始资料清单、client 写入 `inputs/`」的断言。
- `SCN-0307` 运行初始资料（图片）（已建）：上传/删除/绑定/能力缺失的 3 正 1 反。
- 不改变 `SCN-0302`/`SCN-0303`/`SCN-0304` 的现有断言；确认页只增加只读展示。
