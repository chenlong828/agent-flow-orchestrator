# AgentFlow 执行概念设计（工作项目）

## 目的

记录本轮及早前已锁定的技术决策，形成一份可评审、可追溯的概念设计，供后续设计启动使用，不进入实现。

## 范围

- 本地 DSH，使用 ACP 协议；
- 服务端运行时使用 Bun；
- 持久化使用 PostgreSQL（pgsql）；
- 单机开发环境；
- 工作流实例、节点、session、工作区、Skill/工具供给、并发与状态控制；
- 只记录技术决策和已知技术约束。

**不包含**：远程 Harness、生产容量、SLA、性能承诺、排期、验收计划、实现代码。

## 来源

- 本轮技术调研与 ACP 实测结论；
- [`agent-flow-ui` 产品归纳](../../../../agent-flow-ui/docs/design/product.md)及其节点、实例、工作区设定；
- [节点上下文隔离专利 03](../../../../agent-flow-ui/patents/03-交底书-以工作区为唯一信息通道的节点上下文隔离执行方法.md)。

## 设计启动输入

动笔写设计时，先按这张表确认已有决策，再展开模块、表结构和接口。它不是设计规格。

| 设计输入 | 已定决策 | 设计启动时要落的内容 |
|---|---|---|
| 服务端运行时 | D0：Bun | 进程入口、包管理、版本固定、进程守护 |
| 持久化 | D0：PostgreSQL | 表与关系、迁移、连接池、事务、状态查询 |
| 执行协议 | D1：ACP | ACP 客户端、初始化、session 封装 |
| 进程模型 | D2：实例 = 进程 | 进程生命周期、健康检查、退出与清理 |
| 会话模型 | D3：可执行节点/子任务 = session | session 映射、关闭、重试、重跑 |
| 信息通道 | D4：workspace only | 输入/输出声明、评审意见位置、diff 与审计 |
| Skill | D6：控制面内容，原生 catalog 关闭 | Skill 注册表、版本、token、静态/内容接口 |
| 工具 | D7/D8：本地执行，工具表按节点 | 本地工具目录、MCP、执行方式 |
| 并发 | D9：ACP 并发 + Session 并发 | 槽位、队列、公平调度、fan-out 分批 |
| 工作区 | D10：shared / clone / worktree | workspace provider、cwd、worktree 生命周期 |
| 恢复 | D11：直接重跑 | 状态机、幂等、产物版本、审计 |
| 隔离边界 | D5：注意力/逻辑隔离 | 信任假设、共享 workspace 的约束、无硬 ACL 说明 |

## 待定技术问题

| 问题 | 现状 | 设计启动时需要定 |
|---|---|---|
| 默认工作区模式 | 支持 shared / clone / worktree，但未定默认 | 实例默认使用哪种模式；worktree 的启用条件 |
| 并发默认值 | 只有两档模型，未定具体数值 | ACP 并发、fan-out 宽度的配置项和默认值 |
| 本地 PostgreSQL 开发方式 | 已定 PostgreSQL，未定启动方式和版本固定 | 本地开发 PG 的启动方式、版本固定、数据目录 |
| DSH / ACP 版本固定 | 已定本地 DSH，未定固定方式 | 采用哪个版本/来源，如何升级与校验 |
