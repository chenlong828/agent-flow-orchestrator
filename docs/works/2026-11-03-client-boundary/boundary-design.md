# 调度器与 agent-flow-client 边界与职责设计

> 定位：方案与流程框架。本文只回答“谁决定、谁执行、谁持有状态、怎么衔接”，不进入字段级契约、数据库、状态枚举、错误码、本地目录布局与代码。这些留给下一阶段的接口设计。
>
> 来源：执行概念稿 D0–D11、2026-11-02/03 方案讨论结论、现有 B1/B3 契约与 ACP 能力边界。

## 1. 结论摘要

1. **调度器是控制面，client 是执行面。** 调度器决定做什么、什么时候做、结果如何判定；client 只负责在本机把节点执行出来。
2. **状态单家。** 工作流实例、节点状态、session 绑定、技能选择、结果与审计的权威在调度器；client 的本地状态只是执行缓存与恢复日志。
3. **工作区单写。** 本地工作区、技能落地、脚本、产物、会话记录由 client 独占；调度器不读、不写本地文件。
4. **实例粘性。** 一个实例绑定一个 client；client 离线时实例等待或失败，不迁移。产物只在本地，这是必然结果。
5. **一个活跃工作区一个 DSH 进程，一个可执行节点一个 DSH session。** 同一工作区的顺序节点共享进程；fan-out 子任务各自工作区、各自进程；session 是节点级上下文隔离单位，用完即关，不复用。
6. **每节点先建 session，再取技能。** client 建 session 后把 id 交回调度器，调度器返回该节点的技能集合；client 刷新工作区后再执行 prompt。S0 已验证：建 session 后立即写技能，首次 prompt 可见；同 session 替换也可见。
7. **技能选择在调度器，技能落地与隔离在 client。** 模型只应看到当前节点的组合；client 不修改 DSH 内部接口/插件，而是按节点清单直接刷新工作区本地技能文件；只屏蔽全局技能根（用户/打包），保留项目根。脚本随技能包附带，由模型在 session 内调用。
8. **跨边界只回少量结果。** 节点产物留在本地；只回最终消息、状态、停止原因、用量等控制信息；评审与下一节点的判定由调度器完成。
9. **交互走 HTTP 租约/长轮询。** 契约先行，两侧分别开发；字段级契约另立接口设计。
10. **技能可见性已由 S0 验证。** DSH 在 prompt 时读取工作区技能；建 session 后写技能、首次 prompt 可见，同 session 替换也可见。原“若 session 创建时固化技能则调整顺序”的备选不再需要；仍可在实现中先写技能再建 session 作为降低文件系统事件依赖的可选加固，但不改变本文的 session 绑定顺序。

## 2. 定位与边界原则

### 2.1 控制面与执行面

```
调度器（控制面，本仓库）
  ├─ 工作流定义、实例、节点状态与审计
  ├─ 节点选择、分支、评审、fan-out/fan-in
  ├─ prompt 语义、输出契约、技能组合选择
  └─ client 注册、任务租约、session 绑定、结果接收
            ▲
            │ HTTP 租约/长轮询（client 主动出站）
            ▼
agent-flow-client（执行面，独立项目）
  ├─ 实例/分支工作区、技能下载与刷新
  ├─ DSH profile/技能根、进程组与 ACP session
  ├─ 脚本落地、prompt 下发、事件收集
  ├─ 少量结果回传、本地日志与恢复 journal
  └─ 本地产物与工作区清理
```

### 2.2 边界原则

| # | 原则 | 含义 |
|---|---|---|
| 1 | 状态单家 | 调度器是实例/节点状态的唯一权威；client 本地记录只用于恢复，不是第二真相 |
| 2 | 工作区单写 | client 独占本地工作区；调度器不读本地文件，不解释本地产物 |
| 3 | 信息通道 | 节点间通过工作区与 prompt 传递信息；跨边界只传少量控制结果 |
| 4 | 实例粘性 | 实例与 client 绑定；离线等待/失败，不做跨机迁移 |
| 5 | 契约唯一 | 两个项目只通过 HTTP 契约交互；不共享代码、数据库、类型定义 |
| 6 | 失败显式 | client 报告状态与错误；节点级重试由调度器决定，client 只做传输层重试 |
| 7 | 职责单一 | client 不做编排决策；调度器不执行工具、不进入执行链路 |

### 2.3 非目标

- client 不决定下一节点、不判评审、不拆 fan-out、不做回退；
- 调度器不启动 DSH、不读工作区、不执行工具、不解析本地产物；
- 不做跨 client 的实例迁移、共享存储或工作区快照；
- 不做 UI、容量/SLA、远程 Harness、多机调度。

## 3. 职责矩阵

| 事项 | 调度器 | client | 说明 |
|---|---|---|---|
| 工作流定义与版本 | 决定 | 不参与 | client 只接收节点执行请求 |
| 实例创建、生命周期 | 决定并持有状态 | 执行实例的本地准备与清理 | 实例绑定 client |
| 节点选择、分支、评审、fan-out/fan-in | 决定 | 不参与 | client 只执行被下发的可执行节点 |
| prompt 语义与输出契约 | 决定 | 追加执行环境信息 | 业务语义不进入 client |
| 节点技能组合 | 决定 | 落地并刷新 | 调度器按专家装配解析 |
| 技能包下载、校验、解压 | 不参与 | 执行 | 调度器只提供清单与来源 |
| 工作区创建、模式、刷新、清理 | 不参与 | 执行 | 工作区是 client 的领地 |
| DSH 二进制供给与版本 | 不参与 | 执行 | client 负责可用性并上报版本；固定版本/commit |
| DSH profile/技能根 | 不参与 | 执行 | client 屏蔽全局技能根，保留项目根；项目根按 session cwd 解析 |
| DSH 进程 | 不参与 | 执行 | 一个活跃工作区一个进程；实例可含多个 fan-out 分支进程 |
| DSH session 创建与绑定 | 绑定 | 创建并上报 id | session id 由 DSH 生成 |
| 工具与脚本执行 | 不参与 | 执行 | 脚本随技能包；模型在 session 内调用 |
| 权限请求 | 不参与 | 应答/放权 | 按会话/节点整体放权；不依赖工具名做白名单 |
| 本地产物 | 不参与 | 持有 | 不出本机 |
| 节点结果 | 解析与判定 | 生成并上报 | 只回少量信息 |
| 重试与补偿 | 决定 | 执行本次尝试 | client 只重试传输层 |
| 租约、心跳、容量 | 发放与判定 | 上报与续约 | 超时/离线由调度器裁决 |
| 鉴权与审计 | 发放凭据、记录审计 | 持有凭据、上报身份 | 不共享密钥 |
| 观测与排障 | 实例/节点视图 | 本地日志与恢复记录 | 全文不跨边界 |

## 4. 运行与流程框架

### 4.1 运行形态

- **client**：Bun CLI。常驻模式负责领任务与执行；单次模式用于本地调试与 S0 验证。两种模式共用同一执行内核。
- **实例**：一个实例可以有一个主工作区（顺序路径）和多个 fan-out 分支工作区；每个活跃工作区对应一个 DSH 进程（D2 修订）。同一工作区的顺序节点共享该进程；fan-out 子任务各自工作区、各自进程；实例结束时退出所有分支进程。
- **节点**：一个可执行节点（agent / review）对应一个 DSH session（D3）。开始、结束、阶段、人工确认、fan-in 不建 session。
- **工作区**：按实例准备；顺序节点共享同一工作区。fan-out 子任务各自使用独立工作区（clone / worktree），避免并发刷新冲突。跨实例共享工作区与“一个工作区一个进程”存在技能目录争用，默认按实例独立工作区，共享模式需串行或另行约束（见 §8.4）。
- **技能**：按节点组合。client 在 session 创建后刷新工作区技能状态；每个进程使用同一份 skill-filesystem 配置屏蔽全局根（用户技能、打包技能），项目根保留并按 session cwd 解析；节点技能落在 `.dsh/skills` 或 `.agents/skills`。
- **结果**：少量控制信息；本地产物不出机。

### 4.2 主流程

```
调度器                                      client
  │ 创建实例，选择可执行节点                  │
  │ 下发节点执行请求（prompt/输出契约/超时） ─▶│ 领取（租约）
  │                                          │ 确保当前工作区的 DSH 进程（含受控 profile/技能根）
  │                                          │ 建 DSH session
  │◀── 上报 session id ──────────────────────│
  │ 绑定 session 到实例/节点                  │
  │── 返回该节点技能集合 ───────────────────▶│
  │                                          │ 下载/校验/替换工作区技能
  │                                          │ 下发 prompt，消费事件
  │◀── 上报少量结果 ─────────────────────────│
  │ 解析结果，决定下一节点或结束              │
  │                                          │ 关闭 session；实例结束时退出进程
```

关键点：

- 一个节点一个 session；session 关闭后不复用；
- 同一工作区的顺序节点复用进程；fan-out 分支各自进程；一个进程只服务一个工作区；
- client 启动 DSH 时用 skill-filesystem 配置屏蔽全局根；项目根保留；全局技能根不混入；
- 下一节点重新建 session、重新取技能、重新刷新；不沿用上一节点的技能状态；
- 评审节点与 agent 节点走同一流程，client 不解释评审结论；
- 实例结束时统一关闭 session 与进程。

### 4.3 技能供给与工作区刷新

- 调度器按“节点 → 专家 → 技能”的装配关系确定组合，并在 session 绑定响应中返回给 client；client 不访问专家/技能数据库，也不自行选择。
- 技能集合的定制不通过修改 DSH 内部接口/插件实现。client 按调度器返回的清单，直接写入/替换当前工作区的本地技能目录；DSH 原生 catalog 在 prompt 时读取这些文件。每个 worknode 的 session 通过当前工作区（及必要的受控 profile）只看到该节点的集合。
- client 下载技能包、校验完整性、刷新工作区技能状态。刷新是**替换**当前节点的组合，不是叠加；模型在 prompt 时只看到本次组合。
- **技能根隔离是 client 责任。** DSH 的可见技能是多个根（项目 `.dsh`、项目 `.agents`、用户技能根、bundled）的并集；client 只维护 `.dsh/skills` 只能控制该根，其他根仍会贡献技能。client 不删除用户/项目技能根（共享数据、仓库内容），而是通过 skill-filesystem 配置把用户根和打包根指向真实空目录；项目根保留，按 session cwd 解析。项目内 `.dsh/skills` 与 `.agents/skills` 都可作为节点技能落地位置；项目根内已有技能属于项目上下文。每个进程只服务一个工作区，fan-out 分支各自进程。
- S0 已验证：建 session 后立即写技能，首次 prompt 可见；同 session 替换也可见。因此保留“先建 session、再取技能”的顺序，不要求额外的技能生效屏障。
- 脚本随技能包附带；client 只负责落地、赋权、把可用脚本路径告知模型，不执行脚本，也不判断脚本结果。
- fan-out 子任务各自工作区、各自进程，各自刷新；不共享可变技能目录。
- 调度器不参与下载、解压与目录操作。

### 4.4 结果与信息流

- 节点结果只包含最终消息、状态、停止原因、用量、session id 等少量信息；不上传产物、不传完整会话记录。
- 用量从会话事件流收集；不假设 ACP 的 prompt 响应一定返回用量。
- 输出契约由 prompt 定义；调度器解析最终消息并做判定，client 不解析业务字段。
- 评审节点的“通过/不通过”由调度器读取结果后判定，client 只回传模型输出。
- 下游节点依赖同一工作区与上游结果：调度器把上游结果写进下游 prompt，工作区由 client 保留。
- 完整会话记录与日志留在 client 本地，供排障；不跨边界传输。

### 4.5 生命周期框架

| 对象 | 主要阶段 | 权威 |
|---|---|---|
| 实例 | 排队 → 运行 → 等待 client（离线）→ 完成/失败/取消 | 调度器 |
| 节点执行 | 排队 → 已领取 → 会话已绑定 → 执行中 → 完成/失败/取消 | 调度器 |
| DSH session | 创建 → 就绪 → 执行 → 关闭 | client（本地）；id 绑定在调度器 |
| client | 在线/忙碌/离线；有容量/无容量 | 调度器记录，client 上报 |

- 阶段名称是框架语义，不构成状态机枚举；详细状态与迁移在下一阶段设计。
- client 只上报“发生了什么”，不定义“应该进入什么状态”；状态迁移由调度器裁决。

### 4.6 失败、重试、恢复框架

| 失败面 | 责任 | 处理原则 |
|---|---|---|
| 网络/租约/上报 | client | 传输层重试；幂等；不改变业务语义 |
| 技能下载/校验/刷新 | client 报错，调度器决定 | 节点级重试；连续失败则实例失败 |
| 工作区准备 | client 报错，调度器决定 | 重试或失败；不迁移到其他 client |
| DSH 启动/ACP 会话 | client 报错，调度器决定 | 关闭坏 session（close 幂等）；重试当前节点 |
| 节点执行超时/取消 | client 执行，调度器裁决 | 取消 session；按策略重跑或终止 |
| client 崩溃/重启 | client 恢复，调度器裁决 | 按进程组/作业树清理 DSH 与工具子进程；清理/忽略崩溃 session 与锁；重新领取；重跑当前节点 |
| client 离线 | 调度器 | 实例等待或失败；不迁移 |
| 租约过期/迟到结果 | 调度器 | 以当前尝试为准；迟到结果只入审计，不推进流程 |

- 恢复遵循 D11：不依赖 session 恢复或历史回放，直接重跑目标节点；
- ACP 的 close 只保证会话层关闭，不保证工具子进程退出；client 以进程组/作业树作为进程清理边界；
- 暂停优先在节点边界生效；执行中暂停则取消当前 session，恢复时重跑当前节点；
- 重试是否换 client：不换，实例粘性优先。

### 4.7 并发与资源框架

- 两个维度：工作区分支/进程并发（同时跑多少个实例的主工作区与 fan-out 分支）与进程内 session 并发。非 fan-out 每个工作区同时只有一个活跃 session；fan-out 的并发来自多个工作区/进程，不靠同一进程切换不同技能根。
- client 上报容量与健康；调度器只按容量派发，超出排队；client 不自行扩大并发。
- 每个活跃工作区一个进程；fan-out 子任务独立工作区与进程；共享工作区只用于顺序节点。进程数与工作区分支数相关，client 上报容量时按分支计。
- 资源上限（超时、输出大小、磁盘/进程数）由调度器声明、client 执行；具体数值下一阶段定。

### 4.8 安全与信任框架

- client 需要可识别的身份与凭据；注册、心跳、领取、上报都带身份；凭据可轮换。
- 技能包需要完整性校验与受控下载；client 不从不信任来源拉取。
- 远程下发 prompt 与脚本意味着调度器对 client 有执行影响力；这是固有信任面，需要用户授权、来源审计与必要的白名单策略。
- 密钥只在 client 本地；不进入 prompt、日志或上报结果。
- DSH profile 是执行信任的一部分：client 只加载屏蔽全局技能根的 skill-filesystem 配置；不允许用户/打包技能根绕过调度器选择的组合。项目根按工作区保留。
- 权限请求可能不提供工具名/标题，client 只能按会话/节点整体放权；工具可见性由 DSH profile/tool roster 控制，不能把“按工具名白名单”当作权限层保证。
- 审计记录“哪个 client、哪个实例/节点、哪个 session、哪组技能”；具体字段下一阶段定。

### 4.9 可观测性框架

- 关联键：实例、节点、执行尝试、DSH session、client。
- 调度器持有状态视图、结果、时长、错误与审计；client 持有本地日志、会话记录与恢复记录。
- 可选进度事件用于观测；不要求上传完整会话内容。
- 指标、告警、容量承诺不在本阶段。

## 5. 状态与数据所有权

| 数据/决策 | 权威 | 存放 | 说明 |
|---|---|---|---|
| 工作流定义 | 调度器 | 调度器 | client 只读执行请求 |
| 实例/节点状态 | 调度器 | 调度器 | 唯一权威 |
| client 注册与容量 | 调度器 | 调度器 | 心跳更新 |
| session 绑定 | 调度器 | 调度器（id） + client（实际 session） | client 创建并上报，调度器绑定 |
| 技能组合 | 调度器 | 调度器 | client 只落地 |
| 技能包 | 调度器 | 调度器存储 | client 下载缓存 |
| DSH profile/技能根 | client | client | 受控本地配置；调度器只选择技能组合 |
| 工作区/本地产物 | client | client | 调度器不读 |
| 本地日志/会话记录 | client | client | 不跨边界 |
| 节点结果 | 调度器（接收后） | 调度器 + client 本地副本 | 少量信息 |
| 审计 | 调度器 | 调度器 | 记录执行事实 |

规则：

- 每份数据只有一个写入口；client 本地状态是缓存/日志，不是第二权威；
- 调度器与 client 不共享数据库、不互相读表、不共享源码；
- session id 由 client 创建、调度器绑定，两侧都保存，但语义以调度器绑定为准。

## 6. 交互框架

五个交互面，具体字段与端点留给接口设计：

| 交互面 | 方向 | 作用 |
|---|---|---|
| 注册与心跳 | client → 调度器 | 身份、版本、容量、存活；调度器下发控制信息 |
| 任务领取与租约 | client → 调度器 | 领取本 client 绑定实例的节点请求；租约表达“这段时间归你” |
| 会话绑定与技能集合 | client → 调度器 → client | client 上报 session id；调度器绑定并返回该节点技能集合 |
| 结果上报 | client → 调度器 | 少量结果；调度器解析与判定 |
| 取消/关闭控制 | 调度器 → client | 通过心跳/租约通道下发；client 执行并回报 |

交互原则：

- 至少一次投递 + 幂等处理；client 必须能处理重复领取与重复上报；
- 租约到期由调度器裁决；迟到结果只入审计；
- 协议版本可协商；client 版本不兼容时调度器拒绝派发；
- 所有请求带身份凭据；不信任 client 自报的业务状态；
- 传输失败由 client 重试；业务失败由调度器决定是否重试。

## 7. 两项目工作拆分

### 7.1 契约先行

1. 先冻结本文的边界与流程框架；
2. 再立一个接口设计工序，产出字段级契约（端点、载荷、错误、状态、幂等规则）；
3. 两侧按同一份契约分别开发；调度器侧是契约权威，client 侧消费；
4. 契约变更先改规格、再改实现、再通知对方，不允许先改代码后补契约。

## 8. 决策、假设、待定、风险

### 8.1 已定

- client 为 Bun CLI，常驻/单次两种运行方式；
- 调度器与 client 用 HTTP 租约/长轮询；
- 实例绑定 client，离线等待/失败，不迁移；
- 一个活跃工作区一个 DSH 进程；同一工作区的顺序节点共享进程，fan-out 分支各自工作区与进程；一个可执行节点一个 DSH session；
- DSH session id 作为节点/实例的 session 绑定；
- 技能组合由调度器按节点确定，client 建 session 后换取并刷新；
- 脚本随技能包附带，模型在 session 内调用；
- 产物只存本地，跨边界只回少量结果；
- 评审、分支、fan-out/fan-in 由调度器决定；
- DSH 在 prompt 时读取工作区技能；session 后写技能可见（S0 已验证）；
- client 以受控 DSH profile/技能根保证模型只看到当前组合；
- 进程清理以进程组/作业树为边界，不依赖 ACP close。

### 8.2 已验证与剩余假设

S0 已验证：

- DSH 在 `session/prompt` 时读取工作区技能，而不是在 `session/new` 时固化；
- 建 session 后写技能，首次 prompt 可见；同 session 替换也可见；
- DSH 能在同一进程内承载多个 session；close/cancel 行为可用于节点级生命周期；
- skill-filesystem 配置可以把用户/打包技能根指向空目录；项目根保留并按 cwd 解析；脚本可在非交互环境执行；同一进程内不同 cwd 的 session 可按默认项目根隔离。

仍需验证/不作为本文依赖：

- 崩溃时工具子进程的清理（S0-11 失败，client 需进程组/作业树）；
- 权限拒绝路径、`session/resume`、Windows/Linux、DSH 版本固定；
- 一进程承载多个不同工作区时的严格节点集合隔离（本文暂按“一工作区一进程”，该前提可能随全局根屏蔽配置放宽，待复核）。

### 8.3 待定

- DSH profile/patch 的分发、版本与升级方式；
- DSH 二进制版本固定与兼容策略（S0 使用 0.2.2-alpha.2 dev checkout，需固定）；
- 技能包校验和的产生与保存位置；
- client 鉴权方式（令牌/证书/引导凭据）；
- 工作区默认模式、跨实例共享工作区与 fan-out 子任务模式；
- 实例/工作区/日志的保留与清理策略；
- 结果大小上限与传输限制；
- 权限粒度与工具表：permission 元数据不足以按工具名放权，工具可见性如何由 profile/tool roster 控制；
- 契约版本号与兼容窗口；
- 单 client 多用户/多租户场景；
- Windows 支持（进程组/作业对象差异）。

### 8.4 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 全局技能根串味 | 模型看到用户/打包技能，超出项目根范围 | skill-filesystem 配置：用户/打包根指向空目录；项目根保留 |
| 崩溃孤儿进程 | 工具子进程在 DSH 退出后继续运行 | 按进程组/作业树清理；S0-11 已复现 |
| fan-out 进程数膨胀 | 每个分支一个进程，容量与清理成本上升 | client 按分支上报容量；限制 fan-out 宽度；进程树统一收口 |
| 共享工作区与一工作区一进程冲突 | 多实例共享工作区时技能目录争用 | 默认每实例独立工作区；共享模式串行或另行约束 |
| 实例粘性 | client 离线时实例停摆 | 明确为产品约束；后续再评估迁移 |
| 契约漂移 | 两侧字段/语义不一致 | 契约先行、版本协商、样例共用 |
| 远程执行信任面 | 调度器可影响 client 本机执行 | 凭据、审计、授权、白名单策略 |
| 本地产物不可见 | 调度器无法直接审计产物 | 依赖节点结果与评审节点；后续再评估产物上报 |
| DSH 版本/技能行为漂移 | S0 结论在升级后不成立 | 固定版本/commit；升级前复跑 S0 关键用例 |

## 10. 术语

| 术语 | 含义 |
|---|---|
| 调度器 | 本仓库的工作流编排服务，控制面 |
| client | `agent-flow-client`，执行面，Bun CLI |
| 实例 | 一个工作流模板的一次运行 |
| 可执行节点 | 需要 Agent 执行的节点（agent / review）；开始、结束、阶段、人工确认、fan-in 不是 |
| DSH session | DSH ACP 的一次执行上下文；一个可执行节点一个 session |
| session 绑定 | client 创建 session 后把 id 交给调度器，调度器关联到实例/节点 |
| 工作区 | 节点之间与产物的事实源；client 独占 |
| 工作区分支 | 一个实例的主工作区或一个 fan-out 子任务工作区；一个分支对应一个 DSH 进程 |
| 受控 profile | client 启动 DSH 时使用的本地配置：通过 skill-filesystem 把用户/打包技能根指向空目录，保留项目根；不改 DSH 代码 |
| 技能组合 | 当前节点应暴露给模型的技能集合 |
| 租约 | 调度器把某个节点的执行权在一段时间内交给某个 client |
| 少量结果 | 最终消息、状态、停止原因、用量等控制信息，不含产物 |
