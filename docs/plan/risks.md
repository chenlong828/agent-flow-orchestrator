# 风险登记

> 只登记已确认、有触发条件与缓解动作的风险；排期与优先级仍在 `roadmap.md`。

| ID | 风险 | 触发条件 | 影响 | 缓解 / 决策 | 状态 |
|---|---|---|---|---|---|
| `R-001` | 会话日志超限后真实日志不保留 | 单节点某次尝试的日志压缩后超过 `maxSessionLogBytes`（64 MiB） | client 先传 0 行空日志再报 `failed(session_log_too_large)`，任务能结算，但该次尝试的真实会话日志永久丢失 | 2026-11-12 接受：先用 64 MiB 上限，等真实日志体积数据出现后再调阈值或改截断策略（`OQ-27`） | 接受 |
| `R-002` | 会话日志含敏感信息 | 工具输出、命令、环境变量或凭据出现在 ACP 事件里 | 日志完整透传、不脱敏，服务端只存不解析；归档目录可能落盘敏感内容 | 2026-11-12 接受：`archive.root` 与日志目录按运维规范限制访问；排障时离线解析；后续如要脱敏需单独立设计 | 接受 |
| `R-003` | 同键上传后到覆盖 | 同一 `taskId+attempt` 或同一 `runId` 重复上传 | 较晚的重传会替换较早内容，日志/归档可能与当时结算的结果不完全对应 | 2026-11-12 接受：同一 client、同一 attempt/run 内才可能发生；换来「重传无需持久化首次压缩字节」 | 接受 |
| `R-004` | start 节点未按 prompt 写 `intent.md` | 模型未遵循「把诉求写入 task-space/intent.md」的指令 | 后续节点读不到启动诉求，产出可能偏题；编排侧无法直接读 client 目录校验 | 联调 `T-RUN-09` 增加检查；后续可考虑把诉求摘要注入每个节点 prompt 作为兜底（需产品决策，不在本期） | 观察 |
