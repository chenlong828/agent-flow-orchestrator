# JS 后端判断清单

机器规则覆盖不了结构与设计。以下每项在评审时给出「查了什么 / 结论 / 证据位置（文件:行或命令输出）」。没有证据的“已检查”不算。

## 1. 分层与依赖

- **依赖方向**：领域/用例是否反向依赖入口、HTTP、ORM、SDK？第三方类型是否进入公共契约？
- **跨组件相识面**：是否只经 `index.ts` / 契约文件交互？有没有绕过门面直接读内部实现？
- **同层横调**：两个组件是否互相调用又都自称拥有同一能力？共享规则是否抽到稳定层？
- **循环依赖的“合法例外”**：类型-only 导入是否真的只用到类型？运行时会形成环吗？

## 2. 契约与数据

- **单一写入口**：同一业务数据是否有两个写入口？迁移是否只由数据所有者执行？
- **契约完整性**：签名、不变量、错误模式是否写清？新增字段是兼容扩展还是破坏性变更？
- **事务边界**：一个用户动作是否只产生一个事务？跨聚合是否用 outbox/saga 而非放大本地事务？
- **幂等与并发**：重试、去重键、乐观锁、唯一约束是否覆盖真实并发场景？

## 3. 错误处理与边界

- **失败路径**：每个跨边界调用失败时谁重试、谁补偿、谁上报？是否 fail fast？
- **吞错**：`catch` 后只打日志继续执行，是否把业务失败伪装成成功？
- **fallback**：`?? 0`、`|| "Unknown"` 是否掩盖了本应暴露的空值？
- **输入校验**：空、null、超长、非法格式、极端数值、并发重复是否覆盖？校验是否在入口边界？

## 4. 安全与运行边界

- **密钥与日志**：是否有密钥、token、连接串进入代码、日志或错误详情？
- **越权**：鉴权是否在入口完成？资源归属是否校验，而不是只信请求参数？
- **运行时 API**：`Bun.file/sql/write`、`fs`、子进程是否集中在批准的平台/配置模块？
- **路径与注入**：文件路径、SQL、命令拼接是否来自不可信输入？

## 5. 异步、资源与可观测性

- **资源释放**：连接、文件句柄、定时器、监听器是否在失败路径也释放？
- **超时与取消**：外部调用是否有显式超时？长任务能否取消？
- **背压与队列**：无界队列、无界并发是否存在？冷路径是否会拖垮热路径？
- **观测**：关键失败是否有日志/指标，且不泄漏敏感信息？

## 6. 测试有效性

- **断言质量**：是否只断言存在性（`toBeDefined`、`toBeTruthy`）？是否断言具体值、状态或行为？
- **失败覆盖**：每个错误模式是否有测试触发？skip 是否有替身与登记？
- **契约测试**：是否通过公开契约验证，而不是绕过契约测内部？
- **数据测试**：空值、边界、并发、迁移是否覆盖？

## 7. 改动卫生

- **diff 聚焦**：每行改动是否属于本次任务？有没有顺手重构、依赖升级、格式化混入？
- **一个 commit 一件事**：commit message 是否绑定任务与场景？是否可回滚？
- **证据**：测试命令与输出、报告 JSON、校准理由是否留在 task-space？

## 输出格式

```text
[判断项] 分层与依赖
查了什么：读了 X 的 import 与 index.ts 门面；跑了 report 的 Q-07/Q-06
结论：pass / fail / 有条件通过
证据：src/.../x.ts:12；report.json Q-07=0
```
