# 需求拆解

**输入**：`intent.md` 中的用户原话/描述。只读描述；不读项目文档、代码、现有场景，不查历史 task-space。

**输出**：task-space `decompose.md`（回退 `decomposeN.md`），按以下结构写：

1. 原话/描述：逐字摘录关键句；
2. 拆解点：每条可判断，编号 D1、D2……；
3. 真实意图：用户要完成的判断/动作/结果；
4. 用户/角色/时机；
5. 歧义与缺失信息；
6. 假设：标「未经人工」；
7. 待定：需要人工确认的；
8. 从描述可推断的「不做什么」。

**规则**

- 只拆解，不进入方案、场景、需求卡、设计；不写 REQ/SCN。
- 区分「用户说的 / 推导 / 假设」；示例数字、样例默认是示例，不升级为契约。
- 问不出结果的标待定，不自行补；不猜用户意图之外的需求。
- 用常规词，不造缩写；不改仓库、不跑代码。
- 只写 `decompose.md`，不改项目文档。

**自检**

- 每个拆解点可判断；
- 真实意图能回答「用户要完成什么」；
- 歧义、缺失、假设、待定齐全；
- 没有场景/卡/设计内容。

**交接**

- 交人工确认；通过后才进入场景规划。
